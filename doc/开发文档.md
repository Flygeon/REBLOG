## 4. 开发思路（关键设计决策）

### 4.1 为什么是「Vite + Vue 3 自建 SSG」而不是 VitePress
原站是纯静态 SSG 且 `trailingSlash: 'always'`，并有动态路由（`/posts/:slug`、`/2/` 分页）。VitePress 的 URL 由目录结构决定、对 `trailingSlash` 与动态路由控制不足，难以逐字节复刻原 URL。自建 SSG 用 `vue-router` + `@vue/server-renderer` 预渲染，**URL 与 trailingSlash 完全可控**，且天然适配「功能全保留 + 整体重设计」。

### 4.2 URL / trailingSlash 策略
- 所有页面在 `dist/<path>/index.html` 落盘（`/` → `dist/index.html`，`/2/` → `dist/2/index.html`，`/posts/1/` → `dist/posts/1/index.html`）。
- Cloudflare Worker 启用 SPA fallback：未命中静态文件时回退到对应 `index.html`，同时首屏由预渲染 HTML 直出（SEO 友好）。

### 4.3 内容加载策略（P2 核心）
- 不依赖 Astro 内容集合。新建 `src/lib/posts.ts`：构建期用 `import.meta.glob`（`?raw` eager）读 `src/content/posts/*.md` 与 `src/content/spec/*.md`，解析 frontmatter，构建「全量文章 / 排序 / 分页 / 标签 / 分类 / 推荐」数据结构。
- **frontmatter 解析用自研 `src/lib/frontmatter.ts`，不用 gray-matter**：gray-matter 内部依赖 Node 的 `Buffer`，浏览器端（客户端 bundle）会抛 `ReferenceError: Buffer is not defined` 导致整个应用挂载失败（白屏）。自研解析器只覆盖本站 frontmatter 实际形态（标量 / 行内数组 `tags: [a,b]` / 多行数组 `tags:\n  - x` / 引号值 / 布尔 / 数字），兼容 CRLF 行尾（先 `replace(/\r/g,"")`），不依赖任何 Node API，SSR/浏览器行为一致。注意 spec 页（about/friends）本身无 frontmatter，解析回退 slug 属正常。
- `content-utils.ts` 改为纯函数，消费上述数据，保证排序/推荐算法与原站一致。

### 4.4 主题系统
- 保留原 Fuwari 「`--hue` 色相旋转 + oklch 双态」机制（用户可换主题色），外层叠加 **MD3 语义色 token**，组件统一引用 MD3 token，实现「MD3 观感 + 原主题可定制性」兼顾。

### 4.5 音乐引擎重构范式
- `musicEngine` 是 Svelte→Vue 迁移的模板：`svelte/store` 的 `writable` 改为模块级 `reactive` 单例；`<audio>` 仍挂在 `document.body`（路由交换容器之外），实现**跨页面后台播放**。后续 7 个 Svelte 交互组件（Search / LightDarkSwitch / DisplaySettings / ArchivePanel / MemosList / MusicPlayer / MusicPreview）均按此范式转写。

### 4.6 已踩坑（必记）
- **`safe-delete` shim 冲突**：WorkBuddy 沙箱在 `vite build` 清空已有 `dist/` 时超时（`ETIMEDOUT`）。已设 `emptyOutDir:false`，构建前手动 `rm -rf dist` 绕过。
- **npm 源**：全局腾讯云镜像 TLS 不稳定，已在项目级 `.npmrc` 切到 `registry.npmmirror.com`，且确认 `npm` 代理为 `null`（不走代理）。
